# AcademyFlow Starter v0.1

## أدوات التعلّم والمتابعة

التقويم الموحّد متاح للطالب والمدرب وإدارة الأكاديمية. تجد «مساري الدراسي» في بوابة الطالب، و«متابعة الطلاب» لدى المالك والمدير والمدرب. راجع [طريقة الاستخدام وحدود التنبيهات](docs/LEARNING-TOOLS-ar.md). شغّل `npm run test:learning` للتحقق من العزل والصلاحيات والحسابات وواجهات الأدوات.

## تحديث الأمان والاعتمادية

راجع [الإصلاحات ومتطلبات النشر](docs/FIXES-AND-DEPLOYMENT.md) قبل ترقية قاعدة
بيانات موجودة. شغّل `npm test` للاختبارات المعزولة و`npm run demo` لتجربة محلية
مؤقتة. يلزم MongoDB 5+ بنمط replica set ومفتاح JWT عشوائي لا يقل عن 64 حرفاً.
إعدادات الدفع والبريد وWhatsApp والنسخ الخارجية موجودة في `.env.example`؛ لا
تُفعّل الخدمات الحقيقية قبل اختبارها بمفاتيحك. لا تستخدم حسابات التجربة في الإنتاج.

نسخة تأسيسية لنظام SaaS متعدد الأكاديميات، بنفس فلسفة DarbFlow.

1. انسخ `.env.example` إلى `.env`.
2. عدّل `MONGODB_URI` و `JWT_SECRET`.
3. شغّل:
   npm install
   npm run dev

## مهم: السوبر أدمن

## Zoom
AcademyFlow يستخدم **User-managed OAuth** حتى تربط كل أكاديمية حساب Zoom الخاص بها بشكل مستقل.

ضع في Railway:
- `ZOOM_CLIENT_ID`
- `ZOOM_CLIENT_SECRET`
- `ZOOM_REDIRECT_URI=https://academyflow.up.railway.app/api/zoom/callback`
- `ZOOM_TOKEN_ENCRYPTION_KEY` (مفتاح عشوائي طويل؛ وإذا تركته فارغًا يستخدم `JWT_SECRET` كمصدر للتشفير)

لا تستخدم `ZOOM_ACCOUNT_ID` أو `ZOOM_USER_ID` في هذا التدفق.

بعد تسجيل دخول مالك الأكاديمية، يذهب إلى الإعدادات ثم يضغط **ربط حساب Zoom**. النظام يستخدم state موقّعًا وقصير العمر، ثم يحفظ access/refresh tokens مشفّرة داخل سجل الأكاديمية. عند انتهاء access token يتم تحديثه تلقائيًا باستخدام refresh token.

النظام يستخدم Zoom REST API لإنشاء meeting ويحفظ `join_url` و`start_url` في قاعدة البيانات. الفيديو نفسه لا يمر عبر السيرفر، لذلك يبقى النظام أخف.

## حضور Zoom
عند ضغط الطالب زر دخول Zoom من AcademyFlow، يسجل النظام وقت انتقاله إلى Zoom في سجل الحضور المباشر.

للتحقق من الدخول والخروج الفعليين داخل Zoom أضف متغير البيئة:

`ZOOM_WEBHOOK_SECRET_TOKEN`

واضبط Zoom Event Subscription على:

`https://YOUR_DOMAIN/api/webhooks/zoom`

الأحداث المستخدمة:
- `meeting.started`
- `meeting.ended`
- `meeting.participant_joined`
- `meeting.participant_left`

عند توفر بريد المشارك في Zoom، يربطه النظام بحساب الطالب ويسجل وقت الدخول والخروج والمدة الفعلية ويضع علامة "تم التحقق بواسطة Zoom".


## الجداول المتكررة والتنبيهات
يمكن للمالك/الإدمن والمدرب إنشاء جدول محاضرات Zoom متكرر بدل إضافة كل حصة يدويًا.

مثال:
- الدورة: البرمجة
- المجموعة: A أو كل المجموعات
- الأيام: الأحد + الثلاثاء
- الوقت: 19:00
- المدة: 60 دقيقة
- من: 2026-10-01
- إلى: 2026-10-31
- التذكير: قبل 5 دقائق

ينشئ AcademyFlow كل الحصص المطابقة تلقائيًا. كل حصة لها رابط Zoom وسجل حضور مستقل، ويمكن تعديل أو إلغاء حصة منفردة. ويمكن إلغاء كل الحصص القادمة في الجدول مع الاحتفاظ بالحصص السابقة وسجلات حضورها.

### تنبيه الطالب قبل الحصة
عامل التذكيرات داخل السيرفر يفحص الجلسات المجدولة كل 30 ثانية. عند الوصول إلى وقت التذكير:
1. ينشئ إشعارًا داخل بوابة الطالب.
2. يرسل بريدًا إلكترونيًا للطالب إذا كان SMTP مفعّلًا.
3. يستخدم سجل تسليم مستقل لمنع إرسال نفس التنبيه أكثر من مرة.
4. إذا كانت الحصة لمجموعة محددة، يستهدف طلاب تلك المجموعة فقط.

### إعداد SMTP على Railway
أضف المتغيرات التالية:

```env
PUBLIC_URL=https://your-domain.example
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=
SMTP_PASS=
SMTP_FROM_NAME=AcademyFlow
SMTP_FROM_EMAIL=
```

إذا لم يتم إعداد SMTP، تستمر إشعارات AcademyFlow الداخلية بالعمل، ويظهر SMTP كغير مفعّل في صفحة صحة النظام.
